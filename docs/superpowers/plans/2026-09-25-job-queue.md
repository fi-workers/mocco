# Postgres job queue and tick-driven scheduler — implementation plan

**Goal:** durable background work and schedules that behave the same hosted and self-hosted
(platform foundations §7, issue #111). Stacked on #242 (migration 0012), so this slice ships
migration 0013.

**Architecture:** one Postgres table of jobs and one of schedules. `JobRunner.tick` is the only
entry point that drains them; Vercel Cron, a self-host cron or `curl` call it through
`/api/ext/internal/jobs/tick`. `JobQueue.enqueue(…, { kick: true })` also runs the job right away in
`waitUntil`, with the table as the durable fallback.

## Tasks

1. **Schema + migration 0013.** `mocco_jobs` and `mocco_job_schedules` as §7 specifies (partial
   claim index, partial dedupe unique index, status/attempt/interval CHECKs), plus two additions:
   `mocco_jobs.deferrals` (consecutive `RetryAt` count) and a partial unique index on
   `mocco_job_schedules (kind) WHERE workspace_id IS NULL` so system schedules can be ensured
   idempotently. Status constants live in `@mocco/common/jobs`.
2. **Pure policy** (`domain/jobs/policy.ts`): backoff `min(2^attempts * 15s, 6h)` plus up to 25%
   jitter, the interval next-slot calculation, and the `RetryAt` cap. Unit-tested.
3. **`JobRepo`** (pglite tests first): dedupe-aware insert returning the existing job, `claim`
   (one transaction: `SELECT … FOR UPDATE SKIP LOCKED` then `UPDATE` to `running`), `complete`,
   `fail` (reschedule or dead), `defer` (RetryAt), `reclaimExpired`, `prune`. Every write after a
   claim is guarded by the claim's lock token.
4. **`JobScheduleRepo`**: create, `ensureSystem`, `advanceDue` (SKIP LOCKED over due schedules,
   insert a job with `dedupe_key = <scheduleId>:<slot ISO>`, advance `next_run_at` past now).
5. **Handler registry, `JobRunner`, `PostgresJobQueue`**: `tick({ budgetMs, maxJobs })`, `runOne(id)`,
   bad payload → dead, unknown kind → normal failure, `RetryAt` → reschedule without backoff. A tick
   never runs the same job twice (it excludes jobs it already ran).
6. **`jobs.prune`** handler and its daily system schedule.
7. **Transport**: `GET`/`POST /api/ext/internal/jobs/tick` with bearer auth over `CRON_SECRET` or
   `JOBS_TICK_SECRET` (401/503/200 tests via `app.fetch`), env vars in `infra/config/env.ts`,
   `packages/frontend/vercel.json` cron entry.
8. **Composition**: `domain/jobs/instance.ts` → `getJobQueue()` only; `runtime/jobs.ts` →
   `createJobRunner` / `getJobRunner()` builds the registry from each domain's pure handler
   factory, and `kick` reaches it through a dynamic import (no instance.ts cycles).
9. **Docs**: ADR 0014, ADR index + wiki index, `docs/reference/jobs.md`, env reference.

## Review follow-ups (real-Postgres review)

- `maxDuration = 300` on the ext route and `JobTiming` (visibility > max duration > tick budget),
  unit-tested; `JOBS_TICK_BUDGET_MS` clamped.
- `advanceDue` and system-schedule ensuring run statements sequentially (no concurrent queries on
  one client).
- `EnqueueOptions.executor` (transactional enqueue, rollback-tested) and `JobQueue.kick(jobId)`
  for after the commit; `kick` with `executor` throws.
- `ctx.deadline` (= `locked_until`) and a documented overlapping-run rule.
- Tick phases isolated; `TickReport.errors` lists `{ phase, message }`.
- `workspace_id` indexes on both tables (migration 0013 regenerated in place).
- `reclaimExpired` resets `deferrals`; `ensureSystem` updates a changed interval.

## Deferred

- Cron expressions (`cron` column exists, `cron-parser` not added; `JobScheduleRepo.create` only
  takes `intervalSeconds`, and the tick disables a cron row inserted by hand).
- `transport/worker/main.ts`, `yarn worker`, the docker-compose worker service, and
  `JOBS_POLL_INTERVAL_MS` / `JOBS_CONCURRENCY`. Self-host drives the tick with cron + `curl` until
  then.
- The `jobs.dead` domain event (needs #112) and an ops page for dead jobs.
- A real concurrent-connection claim race test (pglite is single-connection; see the reference).
